# Kai Calculator

레스토랑 **팁 분배 계산기**. 매일 낮 팁 · 하루 총 팁 · 서버별 근무 시간을 입력하면
규칙대로 나눠서 **2주 급여 기간 / 월 단위**로 사람별 팁과 근무 시간을 보여줍니다.
데이터는 **Supabase(무료 데이터베이스)** 에 저장되어 어느 휴대폰에서든 같은 내용을 봅니다.

- **급여 기간**: 매달 **1일–15일**, **16일–말일** (리포트의 `2주` 보기)
- **내 시간** 탭: 서버 각자가 자기 이름을 고르면 날짜별 근무 시간과 받을 팁을
  한눈에 봅니다. 종이에 적은 시간과 비교할 때 쓰세요.

## 계산 규칙

| | 공식 |
|---|---|
| 저녁 팁 | 하루 총 팁 − 낮 팁 (자동 계산) |
| 낮, A의 팁 | 낮 팁 × 60% ÷ 모든 서버의 낮 근무 시간 × A의 낮 근무 시간 |
| 저녁, A의 팁 | 저녁 팁 × 60% ÷ 모든 서버의 저녁 근무 시간 × A의 저녁 근무 시간 |
| 주방 / 스시바 | 각 시프트 팁의 40% |

예) 낮 팁 $500, 하루 총 팁 $1,500 → 저녁 팁 $1,000
- 낮: $300(60%) → Alice 6h $180, Bob 4h $120  (나누어떨어지는 예)
- 저녁: $600(60%) → Alice 5h $250, Bob 5h $250, Chris 2h $100
- 주방/스시바: $200 + $400 = $600

### 반올림 규칙 (시프트마다)

각자 받을 팁은 **1달러 단위**로 정합니다.

1. 모두 정확한 몫의 달러 부분만 먼저 받습니다 (예: $60.70 → $60).
2. 소수점이 **.50 이상**인 사람만 1달러 올려줄 후보입니다. **.50 미만은 항상 버립니다.**
3. 소수점이 큰 사람부터 올려주되, 서버들 합계가 **그 시프트 팁의 60%를 절대 넘지 않게** 합니다.
4. **소수점이 같은 사람(같은 시간을 일한 사람)은 함께** 올립니다. 모두 올리면 60%를 넘는 경우에는
   **아무도 올리지 않습니다**. 그보다 소수점이 작은 사람도 올리지 않습니다 (순서를 건너뛰지 않음).

예) 서버 몫 $212.00, 정확한 몫 $50.50 / $60.70 / $60.70 / $40.10
- 모두 반올림하면 51 + 61 + 61 + 40 = $213 → 60% 초과
- 소수점이 가장 큰 $60.70 두 명을 함께 올리고 → 50 + **61 + 61** + 40 = **$212** ✅
- 서버 몫이 $211.90 이었다면 1달러밖에 여유가 없어 $60.70 두 명 모두 올리지 않음 → 50 + 60 + 60 + 40 = $210

반올림 후 서버 몫에서 남은 돈은 리포트에 **남은 금액**으로 따로 표시됩니다 (날짜별 표, CSV에도 있음).
주방 몫(40%)은 반올림과 관계없이 그대로입니다. 서버 몫 %(기본 60)는 관리자가 설정(오른쪽 위 ⚙ 톱니바퀴)에서 바꿀 수 있습니다.

## 권한

| | 직원 (PIN) | 관리자 |
|---|---|---|
| 리포트 보기 | ✅ | ✅ |
| 오늘 날짜 기록 추가·수정·삭제 | **그날 밤 11:59까지** | ✅ |
| 지난 날짜 기록 추가·수정·삭제 | ❌ | 언제든 |
| 서버 추가·이름 수정 | ✅ | ✅ |
| 서버 비활성화·삭제 | ❌ | ✅ |
| 설정, PIN/비밀번호 변경 | ❌ | ✅ |

- 로그인 화면은 하나입니다. **직원 PIN**을 넣으면 직원, **관리자 비밀번호**를 넣으면 관리자로 들어갑니다.
- 한 번 로그인하면 그 휴대폰에서는 직원 30일, 관리자 7일 동안 유지됩니다.
- 모든 규칙은 **데이터베이스 안에서** 검사합니다. 브라우저 코드를 고쳐도 우회할 수 없습니다.
- 날짜와 시간 기준은 **America/Los_Angeles** 입니다. 자정(12:00 AM)이 되면 전날 기록은 잠기고,
  그 뒤에는 관리자만 고칠 수 있습니다. 마감이 자정을 넘기면 관리자가 입력해야 합니다.
- 서버 목록은 어디서나 **이름 순서(알파벳순, 영어 → 한글)** 입니다. 새로 추가하거나 이름을 바꾸면
  자동으로 제자리에 들어갑니다. 서버 **추가는 누구나**, 이미 있는 **이름 변경은 관리자만** 할 수 있습니다.
- 낮 팁과 저녁 팁은 **따로 저장**됩니다. 저녁 탭에서 저장해도 낮에 입력한 내용은 바뀌지 않습니다.
- **자동 저장**: Save 버튼이 없습니다. 입력을 멈추고 1.5초가 지나거나, 다른 칸·날짜·탭으로 옮기거나,
  앱을 내리면 바로 저장됩니다. 팁 입력칸 아래에 **✓ 저장됨 / ⚠ 아직 저장되지 않았습니다(이유)** 가 표시됩니다.
  숫자가 잘못됐거나 팁은 있는데 시간이 없으면 저장하지 않고 이유를 보여 줍니다. 그 상태로 다른 화면으로
  가려고 하면 한 번 더 물어봅니다. 인터넷이 끊겨 실패하면 **다시 시도** 버튼이 나옵니다.
- 기록은 **1년이 지나면 자동 삭제**됩니다. 필요하면 리포트에서 **CSV 다운로드**로 따로 보관하세요.
- **에러 로그**: 저장 실패, 인터넷 끊김, 앱 오류가 생기면 자동으로 기록됩니다 (오프라인이면 휴대폰에 모아 두었다가
  다음에 연결될 때 보냄). 관리자는 **⚙ 톱니바퀴 → 에러 로그**에서 보고, CSV로 받거나 지울 수 있습니다. 90일 보관.

## 설치 (처음 한 번)

### 1. Supabase 데이터베이스 만들기

1. Supabase 프로젝트를 엽니다 (이미 만든 프로젝트: `czplwyojenmnlnbspaep`).
2. 왼쪽 메뉴 **SQL Editor → New query**
3. 이 저장소의 [`supabase/setup.sql`](supabase/setup.sql) 내용을 **전부** 붙여넣고 **Run**
   → `Success. No rows returned` 가 나오면 성공입니다.
4. 새 쿼리 창에서 비밀번호를 설정합니다 (**이 값은 GitHub에 올리지 마세요**):

   ```sql
   select private.set_password('staff', '여기에-직원-PIN');        -- 직원 PIN
   select private.set_password('admin', '여기에-관리자-비밀번호');   -- 8자 이상, PIN과 다르게
   ```

> `setup.sql`은 다시 실행해도 안전합니다 (데이터는 그대로, 함수만 갱신).
> 나중에 코드가 업데이트되면 같은 방법으로 다시 실행하면 됩니다.

### 2. 웹앱과 연결

[`js/config.js`](js/config.js)에 Supabase **Project URL**과 **publishable key**가 들어 있습니다.
(Supabase → Project Settings → API Keys)

- publishable key(`sb_publishable_...`)는 **공개용 키**라서 GitHub에 올려도 됩니다.
  데이터베이스는 `setup.sql`의 함수만 허용하고, 각 함수가 PIN/관리자 세션을 직접 검사합니다.
- ⚠️ **secret key / service_role key는 절대 넣지 마세요.**

### 3. GitHub Pages로 배포

1. GitHub 저장소 → **Settings → Pages**
2. Source: **Deploy from a branch**, Branch: `main`, 폴더 `/ (root)` → **Save**
3. 1~2분 후 `https://pjy990625.github.io/kai-calculator/` 에서 열립니다.
4. 직원들에게 이 주소를 보내고, 휴대폰에서 **홈 화면에 추가**하면 앱처럼 쓸 수 있습니다.

> 무료 GitHub 플랜에서 Pages는 **public 저장소**에서만 됩니다. 저장소에는 비밀번호나
> 팁 데이터가 없으므로 public으로 해도 안전합니다 (데이터는 Supabase에만 있음).

### 4. 첫 설정 (관리자로 로그인)

1. 오른쪽 위 **⚙ 톱니바퀴 → 관리자 설정**: 레스토랑 이름
2. **서버** 탭: 서버 이름 추가

## 매일 사용 방법

1. **오늘 입력** 탭 (기본으로 오늘 날짜). 카드 안에 **☀ 낮 팁 / ☾ 저녁 팁** 두 탭이 있습니다.
2. 점심 후: **☀ 낮 팁** 탭에서 낮 팁과 서버별 ☀ 시간 입력 (자동 저장, ✓ 저장됨 확인)
3. 마감 후: **☾ 저녁 팁** 탭에서 **하루 총 팁**과 서버별 ☾ 시간 입력 (자동 저장, 저녁 팁은 자동 계산)
   - 저녁 탭의 **하루 팁** 칸에는 각 서버가 그날 받는 팁(낮 + 저녁)이 나옵니다.
   - 직원은 **그날 밤 11:59까지** 입력·수정할 수 있습니다. 자정이 지나면 관리자만 가능합니다.
4. 입력하는 동안 각자 받을 팁이 바로 보이고, 반올림 후 남은 금액이 있으면 표 위에 표시됩니다.
5. **리포트** 탭 → `2주` (1–15일 / 16일–말일) / `월` 선택 → 사람별 받을 팁 · 근무 시간, 날짜별 내역(시간당 포함)
   - 이름을 누르면 그 사람의 날짜별 시간이 나옵니다.
   - **CSV 다운로드**(엑셀) / **인쇄 / PDF**
6. **내 시간** 탭 → 내 이름 선택 (휴대폰이 기억함) → 날짜별 근무 시간, 합계, 받을 팁
   - 종이에 적은 시간과 다르면 입력한 사람에게 알려서 고치세요.

## 지원 휴대폰

- **아이폰**: iOS 12 이상 Safari / Chrome
- **안드로이드**: Chrome, 삼성 인터넷 등 최근 브라우저
- 홈 화면에 추가하면 초록색 **K** 아이콘으로 바로 열 수 있습니다
  - 아이폰: Safari 공유 버튼 → 홈 화면에 추가
  - 안드로이드: Chrome 메뉴(⋮) → 홈 화면에 추가
- 입력칸을 눌러도 아이폰에서 화면이 확대되지 않게 했고, 쉼표 소수점(12,50)도 $12.50으로 인식합니다.
- 최종 점검 방법은 [`docs/browser-check-prompt.md`](docs/browser-check-prompt.md)를 보세요.

## 보안 메모

- 직원 PIN이 4자리면 경우의 수가 1만 개뿐입니다. 그래서 틀린 시도가
  **같은 IP에서 15분에 5번**, **전체에서 1시간에 30번**을 넘으면 로그인을 잠시 막습니다.
  그래도 **6자리 이상 PIN**을 권장합니다 (오른쪽 위 ⚙ 톱니바퀴 → 직원 PIN 변경).
  변경하면 이전 PIN으로 로그인한 사람은 모두 로그아웃됩니다.
- PIN이 퍼졌다고 생각되면 바로 바꾸세요.
- 누가 언제 무엇을 바꿨는지는 Supabase **Table Editor → private 스키마 → audit_log**에서
  볼 수 있습니다 (직원/관리자 구분).
- Supabase 무료 프로젝트는 **7일 동안 사용이 없으면 일시 정지**됩니다. 매일 쓰면
  문제없고, 정지되면 Supabase 대시보드에서 Restore를 누르면 됩니다.

## 개발

빌드 도구 없음 — 브라우저가 파일을 그대로 읽습니다.

```
index.html              페이지 뼈대
manifest.webmanifest    홈 화면 아이콘 설정 (icons/)
css/style.css           스타일 (다크 모드, 모바일, 인쇄)
js/compat.js            오래된 휴대폰용 대체 코드 (가장 먼저 로드)
js/config.js            Supabase URL + publishable key (공개값)
js/api.js               Supabase RPC 호출 (fetch, 라이브러리 없음)
js/calc.js              순수 계산 로직 — 60/40 분배, 기간 (DOM/네트워크 없음, 테스트 대상)
js/i18n.js              한국어 / 영어 문자열
js/app.js               화면 (로그인, 입력, 리포트, 서버, 설정)
supabase/setup.sql      DB 테이블 + 권한 규칙 + API 함수
tests/*.test.js         계산 / 번역 단위 테스트 (Node 18+)
tests/db/               setup.sql을 실제 PostgreSQL에서 검증하는 테스트
```

```bash
npm test          # 단위 테스트
npm run test:db   # DB 테스트 (PostgreSQL 15+ 서버 필요, CI에서 자동 실행)
```

- 화면 문자열을 추가하면 `js/i18n.js`의 `en`, `ko` **둘 다** 추가하세요 (테스트가 확인합니다).
- DB 함수에 새 에러 코드를 추가하면 `js/api.js`의 `KNOWN`과 `i18n.js`의 `err_코드`도 추가하세요 (테스트가 확인합니다).
- 사용자 입력은 모두 `textContent`로 넣습니다 (`innerHTML` 금지).
